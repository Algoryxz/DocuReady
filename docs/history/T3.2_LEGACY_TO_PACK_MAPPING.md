## 1. Architectural Pipeline & Execution Separation

In DocuReady, the packet evaluation pipeline executes in distinct stages:
1. **Extraction (`pipeline.py`, `extractor.py`):** Raw PDF text / OCR extractions populate `ExtractedDocument` instances and their `ExtractedField` mappings within `packet.documents`.
2. **Slot Validation (`slot_validator.py`):** Verifies required document slots, anchor text, and language expectations. Mismatched or missing slots produce immediate slot findings and prevent corrupt field data from cascading into downstream cross-document comparisons.
3. **Legacy Hardcoded Engine (`validator.py`):** Historically evaluated 10 statutory rule checks procedurally, generating `Finding` instances with hardcoded messages and statutory references.
4. **V2 Scheme-Pack Engine (`rules/engine.py` & `rules/primitives.py`):** Declaratively evaluates the scheme pack (`packs/<pack_id>/pack.yaml`) using a closed registry of 9 deterministic Python primitives. Primitives produce raw evaluation outcomes (`SATISFIED`, `VIOLATED`, `INDETERMINATE`, `NOT_APPLICABLE`), which are converted into provenance-linked `Finding` objects adhering to the canonical V2 contract.
5. **Outcome Resolution & Safety Layer (`resolver.py`, `safety_layer.py`):** Symmetrically resolves findings into `AuditResult` with `Readiness`, severity caps, and legacy compatibility score snapshots.

## 3. The 9 Closed Primitives Contract Summary

1. `require_document`: Evaluates presence and validity of required document slots in applicant packet.
2. `field_present`: Evaluates existence and non-emptiness of required fields in extracted document data.
3. `match_across`: Evaluates multi-field equivalence using domain-specific match grades (`name`, `date`, `id`, `text`).
4. `within_validity`: Evaluates elapsed time from issuance date to audit reference clock (`as_of`) against statutory expiration periods (`validity_days`, `validity_months`, `validity_years`).
5. `numeric_cap`: Evaluates numeric field against upper threshold (ceiling, `<=`) or lower threshold (cutoff, `>=`).
6. `numeric_consistency`: Evaluates numeric equality across multiple documents within an absolute or percentage tolerance.
7. `age_on`: Evaluates calculated age as of a reference date against minimum and/or maximum age bounds.
8. `enum_in`: Evaluates field membership against an approved list of enumerated string values with deterministic sorting.
9. `legible`: Evaluates scan legibility and extraction confidence threshold without corrupted status.

No primitive allows dynamic code execution (`eval` or `exec`).  
All citations resolve to `sources.yaml`.  
All parameter references resolve to typed `parameters` entries in `pack.yaml`.
All unverified citations preserve the mandatory `[source pending verification]` disclosure.
